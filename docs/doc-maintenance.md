## 配置の原則（正本）

| 置き場 | 公開範囲 | 何を置くか |
|---|---|---|
| `docs/`（GitHub・**公開**） | 公開 | プロジェクトの規約・設計方針・運用手順・再発する技術罠（[tech-notes.md](tech-notes.md) と、そこから分けた [tech-notes-native.md](tech-notes-native.md) / [tech-notes-api.md](tech-notes-api.md)。⚠ **行き先の表は tech-notes.md の冒頭**） |
| `MEMORY.md` + `memory/*`（Google Drive 共有・**非公開**） | 全端末で共有・非公開 | Claude 向け作業ルール（feedback）・端末固有値・GitHub / コードから導けない状態や判断経緯 |
| `docs/archive/`（GitHub・公開） | 公開 | 役目を終えた設計書・計画・廃止手順（参照はするが現役運用しない） |
| chubo2 `docs/infra-note.md`（別リポジトリ・**private**・git 共有） | 全セッション共有・非公開 | サーバーインフラの構成・手順・再発する罠（capsicum の公開 docs に書けない内部情報） |

判断の軸:

- **公開境界**: `docs/` は公開リポジトリ。secrets・端末固有値（UDID / Key ID / 個人ディレクトリパス / SDK パス）・特定運用者の私的判断は置かない → memory へ。**サーバーインフラの内部情報**（内部 SSH ホスト名・ホスティング業者/プラン・deploy ユーザー・server 側コマンド・内部 IP・デプロイ手順）は infra-note へ（移設の手順はスキルの step 4）。
- **二重管理禁止**: GitHub Issues / Releases / Milestones が正本の情報を docs / memory に複写しない。
- **メモリはポインタ運用**: 再発する技術罠の正本は docs（tech-notes 等）に置き、memory 側は一行ポインタ＋「なぜ非自明か」だけ残す構成を既定とする。
- **メモリの役割分担**: `MEMORY.md` は Claude 向け作業ルールと端末固有情報のみ。プロジェクトの規約・方針・手順は docs に書く。
- **メモリは「状態」ではなく「ルール」を持つ**（2026-07-17 方針化）。詳細は下記。

### 1 ファイルは 1 回で読める大きさに収める（#1184）

⚠⚠ **上限は 60,000 バイト。**Read の上限は 25,000 トークンで、このリポジトリの docs は **約 2.55 バイト / トークン**。`deck-ui-plan.md` を 64,720 バイトまで削っても **25,383 トークン**あり、**1 回では読めなかった**（2026-09-30 実測）。実際の限界は **約 63.7KB** で、60,000 はそこへ余裕を持たせた値。⚠ **推定で決めないこと** —— 当初 65KB と見積もって外した。

読めないファイルは「**読まずに書く**」を誘発する。#1184 の直前まで `deck-ui-plan.md` は 100,600 バイトあり、**節番号を名前で参照しているコードがあるのに全文を確かめられない**状態だった。

**直し方は 2 つある**（⚠ **回す手順はスキルの step 6**）。**どちらを採るかは「その節が決着するか」で決める。**

| 直し方 | 当てる相手 | 形 |
| --- | --- | --- |
| **決着した節を [archive/](archive/) へ移す**（#1184 で採った案 A） | 終わった検討・出荷済みの経緯・取り下げた仮説 | 本体には**同じ番号の見出しと結論だけ**を残し、archive へリンクする |
| **別ファイルへ分ける** | ⚠ **決着しないもの** —— 落とし穴集（足し続ける）・現役の設計書（進行で伸びる）・端末別のセットアップ | **入口を 1 つに保つ**。分けた側の冒頭に「何がどこか」を書き、本体には**振り分けの表**を置く |

⚠⚠ **落とし穴集を archive しようとしないこと。**罠は決着しない（踏まなくなるわけではない）。`tech-notes.md` が 86KB になったときに分割へ倒したのはこの理由（2026-09-30）。

⚠ **分けたら「どこへ足すか」を迷わせない。**3 ファイルに割るなら、**迷ったときの既定の置き場**を明示する（`tech-notes.md` は「迷ったらこのファイル」と書いてある）。

⚠⚠ **節番号は振り直さない。**コードのコメントが節を**名前で**参照している（`決定済み事項 10` / `7-3` / `B-1`〜`B-7` 等）。リンクではないので、番号が動いても**どの検査にもかからない** —— だから「移してよいか」は**毎回 grep で実測する**しかない。

⚠ **ファイルごと `archive/` へ動かす操作（スキルの step 5）とは別。**あちらは**役目を終えた docs をまるごと**退かす。こちらは**本体が現役のまま**、決着した節だけを外へ出す。

⚠ **`docs/archive/` は対象外。**「過去の記録・現役運用では参照しない」場所なので 1 回で読める必要がない（`archive/release-log.md` は 112KB ある）。⚠⚠ **逃がし先がここなので、archive を対象に入れるとこの直し方そのものが成立しない。**

⚠ **機械で見ている** → [`packages/capsicum/test/docs_convention_guard_test.dart`](../packages/capsicum/test/docs_convention_guard_test.dart)。超過したまま残るファイルは budget として実測値を記録し、⚠⚠ **budget は下げるだけ**（足すなら同じ回で同じだけ削る）。閾値を下回った budget は「役目を終えた exemption」として落ちるので、**stale な除外が溜まらない**。

⚠⚠ **2026-09-30 に budget は 0 件になった**（超過 4 件をすべて閾値以下へ落とした）。**表が空なのが正常な状態**で、⚠ **次に超過が出たとき、budget を 1 行足して先送りしない** —— その回に削るか分ける。⚠ **ラチェットは「増えないこと」しか見ない**ので、budget を持たせたファイルは**緑のまま永久に 1 回で読めない**（#1184 で実際にそうなった）。

### メモリは status を持たない

メモリに**現況（status）を書くと必ず腐る**。「いま #599 は優先度低」「#474 は未割り当て」と書いた瞬間から、出荷しても誰も書き換えないので、**完了した事案が「これからやること」の顔で残り続ける**。実際 2026-07-17 の棚卸しで、出荷済みの #599 / #474 が「実装フェーズへ」、修正前の #858 が「潰れていた」（＝直った風）と書かれているのを見つけた。**メモリは全端末で共有され、索引（`MEMORY.md`）は毎セッション自動で読まれるため、腐った status は他の端末の判断を直接誤らせる。**

判定は 1 つ:

> **その memory から現況を述べた文を全部消したとき、何か残るか。**
>
> - **残る**（今後守るルール・二度と繰り返さない教訓・まだ効く設計制約・公開 docs に置けない私的判断）→ **その残った部分だけにする**。status は削る。
> - **残らない**（ある時点のスナップショットでしかない）→ **削除する**。

- 進捗そのもの（消化 Issue・公開状況・レビュー結果）は GitHub が正本。退避済みの作業ログは [archive/release-log.md](archive/release-log.md)。マイルストーン進捗メモリの扱いは [milestone-transition スキル](../.claude/skills/milestone-transition/SKILL.md) の「完了後」を参照。
- **完了・断念した事案でも、そこから抽出した「今後どうするか」が残るなら、ルールとして書き直して残す**（例: Flathub は断念済みだが「再提案しない」＋「外部に出す文章は人間の所有権を通す」が残る / Mastodon 4.6 対応は完了だが「pooza は本番をリリース日にデプロイする＝上流 GA 前に互換を確定させる」が残る）。
- 削除・圧縮の前に、**GitHub や docs からは読めない事実**（資格情報の満了日・環境の癖・因果の発見・私的判断）が埋もれていないか確認し、あれば先に docs か `reference_*` へ昇格させる。memory は git 管理外なので、消すと復元できない。
