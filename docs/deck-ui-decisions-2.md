### 14. アカウントをまたぐカラムは、アカウントを持たないものとして扱う（2026-10-09 pooza 決定・[#1259](https://github.com/pooza/capsicum/issues/1259)）

対象は「すべての通知」（`AllNotificationsTab`）。中身が全アカウントのものなので、カラムが保存形式の都合で持っているアカウントは**中身と対応しない**。種別の側に `TabType.spansAccounts` を持たせ、次の 5 つをそこから決める。

| | 決めたこと |
| --- | --- |
| 列の中の本数 | **1 本だけ。**どのアカウントのカラムにフォーカスして開いても、既にあればそこへ送る。カラム編集から足しても増えない（決定済み事項 6-2 の「重複を許す」の例外） |
| 既に複数本できている列 | **読み込み時に 1 本へ畳む**（いちばん左を残す） |
| 動かすアカウント | **現在のアカウント。**保存されているアカウントは見ない（`DeckColumn.effective`）。⚠ 開いたときのアカウントに縛ると、そのアカウントをログアウトした時点でカラムごと「表示できません」になる |
| 見出し | **アカウントを出さない**（アイコン・表示名・サーバーの色）。題だけ。帯（決定済み事項 13）・カラム編集のシート・メニューバーの「表示 > カラム」も同じ |
| 簡易投稿バー・⌘N | このカラムにフォーカスしているときは**現在のアカウント**。バーは左端にアイコンを出すので、誰として投稿するかは見える。⚠ 見出しの鉛筆は出さない（決定済み事項 13・#1255） |

- ⚠ **保存形式は変えていない**（`<id>|<アカウント>|<種別>` のまま）。アカウントの欄は埋まっているが、読む側が使わない。設定バックアップも従来どおり通る
- ⚠ **アカウントをまたぐ種別を足すときは `spansAccounts` を立てるだけでよい**（上の 5 つが付いてくる）。⚠ 種別名で分岐を書き足さない

### 15. デッキにも、タブ表示と同じドロワーを置く（2026-10-11 pooza 決定・[#1272](https://github.com/pooza/capsicum/issues/1272)）

メニューバーの無い端末（Android / iOS / iPad）では、ブックマーク・リスト・予約投稿などへデッキから届かず、使うたびにタブ表示へ切り替える必要があった。スマホでデッキを常用するための対策で、[#1271](https://github.com/pooza/capsicum/issues/1271)（カラムのロック）と対になる。

| | 決めたこと |
| --- | --- |
| 入口 | **AppBar の左端にハンバーガー。**左端は空いていた（戻る矢印も題も置いていない）ので、右側のアイコンは 6 つのまま（決定済み事項 13 の「歯車を足す」は変えない）。幅に依らず出す |
| 重ね方 | **タブ表示と同じドロワー**（`buildHomeDrawer`・`home_drawer.dart`）。項目は同じ定義（`buildHomeNavItems`）から作り、別に並べ直さない |
| 常駐 | **させない。**決定済み事項 7-1 / 8 が禁じているのは広い幅で出しっぱなしになるドロワーで、押したときだけ重なるものは当たらない |
| アカウントの切り替え | **持ち込まない**（一覧ごと出さない）。現在のアカウントが変わるとカラムのコンテナの割り当てが組み替わる（決定済み事項 8 / 11）。追加・この端末から削除（旧「ログアウト」）・未接続アカウントの復帰は残す（メニューバーと同じ線） |
| 左端からのスワイプ | **開かない。**狭幅のデッキは横スワイプでカラムを移るので、左端で競合する。ボタンからだけ開く |

- ⚠⚠ **ドロワーの組み立てはウィジェットにしていない**（呼び出し側の `context` と `ref` で組む関数）。項目の多くはドロワーを閉じたあとに `ref` を使う（ログアウトの確認 → 実行など）ので、ドロワーの子として独立させると、閉じた時点で `ref` が捨てられて後続の処理が落ちる
- **開いた先は、選ぶと TL になるものだけカラム**（2026-10-12 pooza）。「カラムにできるものは全部カラム」は採らない（列が増えやすい）。カラムはフォーカス中のカラムの右隣に足す
  - 入っているのは**リスト・チャンネル・プロフィールタグ**（`buildHomeNavItems` の `columnContext`）
  - ⚠ **アンテナとクリップは全画面のまま。**カラムの種別がまだ無い（足すなら保存形式・見出し・`canComposeFromColumn` の列挙まで要る）
- ⚠⚠ **2026-10-15 に改めた（[#1286](https://github.com/pooza/capsicum/issues/1286)・pooza 決定）: ドロワーを開くとき、現在のアカウントをフォーカス中のカラムのアカウントへ切り替えてから開く。**実際に使ってみて、別アカウントのカラムを見ながらそのアカウントのブックマーク等を開くのに、いちいちタブ表示へ戻るのが重かった
  - 項目・ドロワーの頭・そこから開いた全画面は、どれも**現在のアカウント**で動く（下の取り下げた理由はそのまま効いている）。開く前に現在のアカウントを合わせることで、途中でアカウントが入れ替わらない
  - ⚠⚠ **切り替えのきっかけはドロワーを開くときだけ。**現在のアカウントが変わると、前後 2 アカウントのカラムがルートとアカウント別のコンテナの間で組み替わり、**作り直し（スクロール位置が先頭へ戻る・取り直し・ストリーミングのつなぎ直し）**になる（決定済み事項 8）。フォーカスの移動ごとに追従させる案（狭幅ではスワイプのたび）と、止まってから切り替える案は、そのたびにこれが起きるので採らない（2026-10-15 実測）。ドロワーを開くのは「そのアカウントのものを開きたい」意図がはっきりしている回で、作り直しが起きるのもその回だけ
  - アカウントをまたぐカラム（決定済み事項 14）にフォーカスしているときは切り替えない
  - カラムで開く 3 項目（リスト・チャンネル・プロフィールタグ）は、**一覧を引いた時点のアカウントを明示して開く**（`open*` の `account:`）。確定の時点がずれて、一覧と違うアカウントのカラムになるのを防ぐ
- ~~**項目を開くアカウントは、現在のアカウント**（2026-10-12 pooza）。~~ → 上の 2026-10-15 の決定で、開く前に現在のアカウントをフォーカスへ合わせる形になった。ドロワーの頭にも現在のアカウントが出ているので、誰のものを開くかは見えている
  - ⚠ **「フォーカス中のカラムのアカウント」は採らない。**同日いったんそう決めたが、取り下げた。全画面で開く画面へアカウントのスコープを運ぶ仕組みが、投稿フォーム・メディアビューア・プロフィール編集にしか無い（`extraWithProviderScope`）。別アカウントのスコープでブックマーク等を開いても、**そこから投稿を開いた時点で現在のアカウントへ戻り、別サーバーの id を現在のアカウントで引く**（#1150 と同じ穴）
  - 採らなかった案: カラムで開く項目だけフォーカス中のカラムに合わせる（1 つのドロワーの中でアカウントが混ざる）/ フォーカスが別アカウントのときは全画面の項目を出さない（別アカウントのブックマーク等には結局届かない）/ 全画面の画面にもスコープを運ぶ（デッキの外の画面遷移全体に触る）
- ⚠ **暫定のまま残っているもの: 「デッキ」「検索」「通知」「すべての通知」の項目。**いまは出していない。「デッキ」は押すとデッキ画面が 2 枚積まれる。検索・通知は AppBar に入口があり、そちらはカラムで開く —— ドロワーから開くと全画面になり、決定済み事項 7-3 が採らなかった形（結果から開いた先がデッキの外へ出る）になるため

### 16. カラムはロックできる（2026-10-12 pooza 決定・[#1271](https://github.com/pooza/capsicum/issues/1271)）

デッキの構成を固定して使っていると、操作の結果として挿入されたカラム（スレッド・検索など）を閉じるつもりで、常設のカラムを閉じてしまうことがある。狭幅ではカラムを 1 本ずつ見るので、押し間違えたときに失うものが大きい。

| | 決めたこと | 採らなかった案 |
| --- | --- | --- |
| 形 | **ロックの操作を足す。**ロックしたカラムは見出しの × では閉じられない。ロックしなければ今と何も変わらない | 「あとから挿入されたカラム以外は閉じられない」（入口は保存しておらず、種別からは推し量れない・決定済み事項 9-2）/ 閉じた直後の「元に戻す」（構成を固定したい、には応えない） |
| 単位 | **カラムごと** | 「いまの構成を固定する」の 1 操作（常設を足すたびに掛け直しが要る） |
| 見せ方 | ロック中は **× の位置に鍵**を出し、押すと解除（閉じるには 2 回押す）。掛かっていないカラムには、× の左に控えめな開いた鍵 | ロック中は × を出さないだけにし、掛け外しはカラム編集のシートで行う |

- **ロックが止めるのは見出しの × だけ。**カラム編集のシート（意図して開く場所）からは外せる。中身の画面が自分で閉じる経路（コレクションを削除した等・`screenCloser`）も止めない —— 残すと「表示できません」のカラムになる
- 並べ替えは対象にしない
- ⚠ **列の外に id で持つ**（`deck_locked_columns`・最後に見ていたカラム #1239 と同じ形）。保存形式 `<id>|<アカウント>|<種別>` は動かしていない。列に居なくなった id は落とす
- ⚠ **設定のバックアップには含める**（2026-10-19 pooza・[#1317](https://github.com/pooza/capsicum/issues/1317) で書き換えた）。当初は「id は列の中だけで通じる番号で、取り込み先の列では別のカラムを指しうる」として外していた。ところが取り込みは列を丸ごと置き換え、id もそのまま書くので、**取り込んだ列の中では通じる**。節 `deck_locked_columns:` に、書き出した列に居る id だけを書き、取り込むのは取り込んだ列に実在する id だけ。線（構成とユーザーが付けた印は含める・寸法と「最後にどこにいたか」は外す）は `settings_backup.dart` の `deviceLocalKeys` の doc
